  1. Start with a PocketBase instance.

    Request managed hosting, or deploy PBManager on your own server. An administrator provisions your instance.

  2. Create a token in Agents & MCP.

    Name your agent and assign its token to one instance or all managed instances. Save the token when it’s shown.

  3. Connect your client and start building.

    Add the endpoint and token using the dashboard’s connection snippet. Ask your agent to list its instances, then choose the database to work with.

Instance-scoped, with administrator access. A token grants superadmin read/write access to the assigned PocketBase APIs, including settings and superusers. Choose the instance deliberately. You can revoke tokens in PBManager; agent API actions are recorded without request bodies or credentials.

Is this a different database from PocketBase?

No. Your data lives in a real PocketBase instance, with its usual collections, records, authentication, file storage, and APIs. PBManager adds hosting, management, and an MCP connection for your agent.

Does it automatically remember every conversation?

No. Your agent explicitly writes records or tasks and retrieves them when needed. You decide what it should store. Shared tasks live in PBManager; application records live in the selected PocketBase instance.

Can an agent provision servers through MCP?

The current MCP tools work with existing managed instances and shared tasks. An administrator provisions instances in PBManager. MCP tokens do not grant shell access or access to the manager’s private administration API.

Can I try it before requesting hosting?

Explore the dashboard demo to try instance management with browser-local sample data. Live MCP access requires a running manager, a PocketBase instance, and an agent token. Hosting availability, resources, and pricing are confirmed when you request access.
